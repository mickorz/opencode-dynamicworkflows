# 优化档案 schema：文档结构、指标口径与写入时机

每个被优化的 workflow 一套档案，三个文档，与演进报告同目录（目录推导规则见 SKILL.md）：

| 文档 | 命名 | 角色 |
|------|------|------|
| 优化台账 | `<workflow-name>-优化台账.md` | 每版一行的流水索引，闭环各步陆续补列 |
| 指标对比 | `<workflow-name>-优化指标对比.md` | 指标 x 版本矩阵，趋势对比的唯一数据源 |
| 遗留问题清单 | `<workflow-name>-遗留问题清单.md` | 跨版记忆载体，问题生命周期状态流转 |

演进报告仍是每版一份的深度分析；台账是它的索引，不重复其内容。

## 一、优化台账（每版一行）

| 列 | 必填时机 | 口径 |
|----|---------|------|
| 版本 | 第 1 步备份时 | vN |
| 日期 | 第 1 步 | YYYY-MM-DD |
| 主题标记 | 第 1 步 | 备份文件名中的短代号 + 一句话主题 |
| 备份文件 | 第 1 步 | 相对脚本目录的文件名 |
| runId | 第 3 步执行后 | 执行 run 的 id |
| 耗时s | 第 3 步 | 秒，执行 run 总耗时，不含评审 run |
| token | 第 3 步 | 执行 run 总量 |
| 轮次 | 第 3 步 | 检查修复闭环走了几轮 |
| 结果 | 第 3 步 | passed / failed |
| 自评 | 第 3 步 | RED/O/Y，必须与产物报告明细行数对账后填 |
| 奖牌 | 第 5 步报告后 | 本版在多维评审综合排名的奖牌数（如 4 金 1 铜） |
| 报告路径 | 第 5 步 | 演进报告相对路径 |
| 遗留数 | 第 5 步 | 该版报告遗留问题清单条数 |

台账行一旦写入历史版本不再改写；写错当版可修正并注明。

## 二、指标对比（指标 x 版本矩阵）

按指标组分三节，每节一张表：行为指标，列为版本。口径写死，禁止每版自创口径。

### 2.1 执行元指标（每版必填，来自 run 结果，不手填）

| 指标 | 口径 |
|------|------|
| 耗时 / token / 轮次 / 结果 / 自评 | 同台账，数值必须一致 |

### 2.2 机制指标（每版必填，程序化复算，可版本间归因）

| 指标 | 口径 |
|------|------|
| 编号落地率 | 连续唯一编号的数据行数 / 数据行总数，百分比；评审 agent 复算 |
| 占位残留数 | AUTO、SPEC-ITEMS、{xxx} 等占位符在产物与报告中的出现总数 |
| 闸门一致性 | 机械结论与报告结论双向一致为"一致"，否则"冲突"（二值） |
| 自评对账偏差 | RED/O/Y 声明值与明细行数之差，0 为合格 |
| 锚点悬空数 | 产物引用的源锚点在源文件中不存在的数量 |
| 表格结构一致率 | 表头列数与数据行列数一致的表占比 |

### 2.3 内容指标（波动观察，尽力填，只观察不归因）

| 指标 | 口径 |
|------|------|
| 数据行总数 | 全部产物文件数据行求和 |
| REQ 密度 | 产物引用的唯一源锚点数 |
| 关键覆盖项 | 按 workflow 领域选定（如术语对照项数、专行覆盖数），初始化时在表上方注明本 workflow 选了哪些项 |
| 遗留修复数 / 新增数 | 本版修复上版遗留的条数 / 本版新发现的条数 |

矩阵下方必须保留一行说明：机制指标版本间可比可归因；内容指标受随机波动影响，趋势参考、不单独归因。

## 三、遗留问题清单（问题生命周期）

| 列 | 口径 |
|----|------|
| ID | L1、L2…顺序编号，不复用 |
| 严重度 | 高 / 中 / 低 |
| 问题描述 | 一句话，含产物位置（文件:行或编号） |
| 发现版本 | vN |
| 状态 | 未修 / 已修 / 部分修复 / 不修（需注明理由） |
| 修复版本 | 修复落地并通过验证的版本 |
| 验证方式 | 可复算的验收口径（如"复算残留数为 0"） |

状态流转规则：

- 新发现 → 追加行（第 5 步报告定稿时）
- 修复 → 状态改已修 + 填修复版本 + 验证方式（第 6 步参悟核对真实修复后才改，禁止凭报告自述改状态）
- 连续两版处于未修且无排期 → 标注"跨版失忆风险"，下版设计时强制纳入

## 四、写入时机矩阵（闭环步骤 x 文档）

| 闭环步骤 | 优化台账 | 指标对比 | 遗留清单 |
|---------|---------|---------|---------|
| 第 0 步初始化 | 建文档与表头 | 建文档、三组表头、注明内容指标选型 | 建文档与表头 |
| 第 1 步备份 | 追加当版行（版本/日期/主题/备份文件） | - | - |
| 第 3 步执行 | 补 runId/耗时/token/轮次/结果/自评 | 补执行元指标列 | - |
| 第 4 步评审 | - | 补机制与内容指标列（复算值） | - |
| 第 5 步报告 | 补奖牌/报告路径/遗留数 | - | 新发现问题追加行 |
| 第 6 步参悟 | - | - | 核对修复状态、标注跨版失忆风险 |

初始化幂等：三个文档已存在则跳过创建，只做列完整性检查（缺列补表头，不动已有数据）。
