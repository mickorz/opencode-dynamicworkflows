# P4 阶段手动测试指南（Workflow 自优化闭环）

> 本指南在 `dev-examples/development-trace/` 目录下手动验收 P4 全链路：
> 跨 Run 聚合 -> 候选生成 -> 双 worktree A/B 验证 -> 人工审批 -> 多文件事务应用。
>
> 配套自动检查脚本：`scripts/p4/p4-full-check.ts`（断言落盘数据）；
> 环境重置：`scripts/p4/cleanup-p4.ts`；聚合专项检查：`scripts/p4/verify-p4-aggregation.ts`。

## 0. 前置条件

1. **编译最新插件**（P4 代码在 dist 里，OpenCode 从 dist 加载）：

   ```
   cd <仓库根>
   npm run build
   ```

2. **进入联调目录启动 OpenCode**（本目录的 opencode.json 已配置 plugin 指向仓库根）：

   ```
   cd dev-examples/development-trace
   opencode
   ```

3. **重置验收环境**（新终端，在本目录；含 git 还原目标脚本为原版——上次验收可能已应用候选版）：

   ```
   npx tsx scripts/p4/cleanup-p4.ts
   ```

4. 目标 Workflow 为 `scripts/p3/p3-analyzer-verify.js`（已在 git 跟踪，worktree 可见），
   其 Phase 2 让 Agent 每次重写 `p3_validate.py`，Phase 4 执行它——正是 P4 要固化的重复工作。

说明：本目录 opencode.json 的 `optimization-approve:*: allow` 是 **CLI（opencode run）驱动验收用的预授权**；
交互式会话可改回 `"ask"`（默认弹窗批准，语义更严）。

## 1. Test 1：跨 Run Exact 聚合触发（P4-A）

**目标**：同一 Workflow 跑两次后，聚合器识别同一 fingerprint 且 distinctRunCount=2，自动创建 OptimizationJob。

在 OpenCode 会话中执行（两次，可分两条消息）：

```
调用 workflow 工具，参数：scriptPath: "./scripts/p3/p3-analyzer-verify.js"，development: true，background: false
```

每次执行后等待 DevJob（Optimizer）完成——观察输出中 Optimizer Job 状态，或另开终端轮询：

```
npx tsx scripts/p4/verify-p4-aggregation.ts
```

**第一次运行后预期**：
- `[manifest] ...: workflowSource = {"kind":"file","scriptHash":"17b9bb...","scriptPath":"...p3-analyzer-verify.js"}`
- `[candidates] fp=4b3fa726 ... occ=1 runs=1`（不创建 Job：runs < 2）

**第二次运行 + DevJob 完成后预期**：
- `[candidates] fp=4b3fa726 ... occ=2 runs=2 eligible=true`
- `development/optimization-jobs.json` 出现 1 条 Job：`4b3fa726-17b9bb-a1`，state=`aggregated`

自动检查：

```
npx tsx scripts/p4/p4-full-check.ts aggregation
```

## 2. Test 2：候选自动生成 + A/B 验证推进（P4-B + P4-C）

**目标**：第二个 DevJob 完成触发自动链——B 生成候选（固化工具 + Workflow Patch），C 在双 worktree 隔离执行 A/B 并跑三道闸门，Job 停在 `awaiting_approval`。

此链在插件进程内自动执行（DevJob completed 回调驱动，fire-and-forget）。
**关键：保持 OpenCode 会话存活**（A/B 共约 10 个 Agent，需 2-5 分钟，进程退出会中断）。

等待方式（另开终端轮询，或用 workflow_control 观察后台 run）：

```
node -e "const t=setInterval(()=>{try{const j=require('./.opencode-workflows/development/optimization-jobs.json');const s=j.jobs[0].state;console.log(new Date().toLocaleTimeString(),s);if(s!=='aggregated'&&s!=='planned'&&s!=='generated'&&s!=='validating')clearInterval(t)}catch(e){}},15000)"
```

**预期终态**：`awaiting_approval`（三闸门全过）或 `failed`（闸门未过，见 ab-result.json 或重跑）。

自动检查（候选产物 + A/B 结果 + 状态一致性）：

```
npx tsx scripts/p4/p4-full-check.ts
```

重点关注：
- `candidates/4b3fa726/candidate.js`：写脚本节点的 prompt 已收窄为"确认固化工具可用"，
  执行节点命令变为 `python tools/p3_validate.py opencode.json`；agent 调用数不变（narrow-scope）
- `candidates/4b3fa726/solidified-tool.py`：与历史 `p3_validate.py` 内容一致
- `candidates/4b3fa726/ab-result.json`：三闸门明细 + token/耗时对比
- **原 `scripts/p3/p3-analyzer-verify.js` 未被修改**（P4 第一版不自动覆盖）

失败排查：
- state 停在 `aggregated`：自动链未触发（DevJob 未 completed，或 dist 未更新）
- state=`failed`：看 `candidates/4b3fa726/` 是否有 ab-result.json；
  无则候选生成失败（歧义/语法/基线不符），有则闸门未过（看 evaluation.details）

## 3. Test 3：查看任务（optimization_control 工具）

在 OpenCode 会话中：

```
调用 optimization_control 工具，action: "list"
调用 optimization_control 工具，action: "status", optimizationId: "4b3fa726-17b9bb-a1"
```

**预期**：list 列出任务与状态；status 展示目标、基线哈希、候选、固化工具、A/B 摘要、预期改进。

## 4. Test 4：拒绝路径（P4-D，原文件不动）

先复制原文件哈希留证（另开终端）：

```
node -e "const c=require('crypto'),f=require('fs');console.log(c.createHash('sha256').update(f.readFileSync('scripts/p3/p3-analyzer-verify.js')).digest('hex'))" > /tmp/before.txt
```

在 OpenCode 会话中：

```
调用 optimization_control 工具，action: "reject", optimizationId: "4b3fa726-17b9bb-a1"
```

**预期**：Job -> `rejected`；输出"原文件未做任何修改"；重新计算哈希与 before 一致；
`development/approval-records/` 无记录；无 apply-log。

（拒绝后如需重新验收 Test 5，重置环境从 Test 1 重跑；或等新 Run 增长 distinctRunCount 自动开新一轮。）

## 5. Test 5：批准与应用路径（P4-D 多文件事务）

前置：Job 处于 `awaiting_approval`（重置后重跑 Test 1/2，或直接接着 Test 2 的终态）。

在 OpenCode 会话中：

```
调用 optimization_control 工具，action: "approve", optimizationId: "4b3fa726-17b9bb-a1"
```

**前台弹出批准确认**（optimization-approve 权限）——选择允许。

**预期结果**：
1. `scripts/p3/p3-analyzer-verify.js` 被替换为候选版（哈希 == plan.candidateScriptHash）
2. `tools/p3_validate.py` 固化工具部署成功（新文件）
3. `candidates/4b3fa726/backup/` 有原版备份
4. `candidates/4b3fa726/apply-log.jsonl` 追加 applied=true 台账
5. `development/approval-records/4b3fa726-17b9bb-a1.json` 存在（approvalChannel=ask:<sessionId>）
6. Job -> `applied`

自动检查：

```
npx tsx scripts/p4/p4-full-check.ts apply
```

**拒绝批准路径**：在弹窗选择拒绝 -> 输出"用户未批准，原文件未做任何修改"，Job 保持 awaiting_approval。

**应用失败回滚**（可选验证）：手动篡改 `tools/p3_validate.py` 目标位置为一个已存在文件后
approve（新文件基线 <absent> 与已存在冲突）-> 输出"应用失败"，Workflow 文件不变。

## 6. Test 6：应用后行为验证（优化生效）

应用成功后，清掉旧运行残留再跑一次：

```
（另开终端）rm p3_validate.py
（OpenCode 会话）调用 workflow 工具，参数：scriptPath: "./scripts/p3/p3-analyzer-verify.js"，development: false，background: false
```

**预期**：
- 执行日志中"写入脚本"阶段的 Agent 不再创建 `p3_validate.py`，而是直接运行 `tools/p3_validate.py`
- Phase 4 执行命令为 `python tools/p3_validate.py opencode.json`，输出 `valid`
- 运行结束后项目根**不再产生**新的 `p3_validate.py`（固化生效）

## 7. 验收状态速查表

| 阶段 | 落盘证据 | 检查命令 |
|------|---------|---------|
| A 聚合 | `development/aggregated/candidates.json`、`development/optimization-jobs.json` | `npx tsx scripts/p4/p4-full-check.ts aggregation` |
| B 候选 | `candidates/<fp>/optimization-plan.json` + `candidate.js` + `solidified-tool.py` | `npx tsx scripts/p4/p4-full-check.ts candidate` |
| C A/B | `candidates/<fp>/ab-result.json`（三闸门） | `npx tsx scripts/p4/p4-full-check.ts ab` |
| D 批准 | `development/approval-records/<id>.json` | `npx tsx scripts/p4/p4-full-check.ts approval` |
| D 应用 | `apply-log.jsonl` + `backup/` + 目标文件哈希 | `npx tsx scripts/p4/p4-full-check.ts apply` |

## 8. 已知边界与排障

| 现象 | 原因与处理 |
|------|-----------|
| opencode run（CLI）驱动时 Optimizer/自动链中断 | CLI 进程退出会杀插件进程内的后台执行；**交互式会话**或让 Main Agent 轮询到终态保活 |
| A/B 双侧 token 接近或候选反超 | 模型输出波动；闸门要求至少一项改善，重跑一轮可能通过；持续不过说明收益不成立（正确拒绝） |
| 候选生成 failed：定位歧义 | 目标文件名出现在多个 Agent 节点（P0 契约禁止自动 Patch），转人工 |
| worktree 创建失败 | 非 git 目录或 git 不可用；强隔离契约直接拒绝，不降级 |
| Windows 短路径名（ZHANGQ~1） | 已在 ab-runner 用 realpathSync.native 归一；自写脚本做路径拼接时注意 |
| 目标脚本未提交 git | worktree 从 HEAD 创建，未提交文件不在 worktree 内（相对引用会断）；先 git add+commit |
| 第二次 approve 提示状态不符 | Job 已终态；等新 Run 增长 distinctRunCount 后聚合会开新轮次（attempt+1，上限 3） |

## 9. 本轮实机验收结论（参考基线）

全链路已实机验证通过（p4-full-check 全部通过）：
- 聚合：2 个独立 Run distinctRunCount=2，自动创建 Job
- 候选：replace-with-tool（写脚本 Agent -> 零 token check）+ 执行路径替换，原文件验收期间未动
- A/B：双 worktree 隔离执行，三闸门全过（token 1260->1087，确定性命令 stdout 哈希一致，原项目未修改）
- 审批：ask 通道批准 -> ApprovalRecord -> 多文件事务应用 -> applied
- 效果：优化版 Workflow 4 个 Agent（原 5 个）成功执行，项目根不再产生临时脚本，耗时 24.7s
