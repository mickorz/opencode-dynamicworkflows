## 1. 一句话机会

OpenCode 重度用户跑大批量并行任务时主上下文被撑爆，本插件用"自然语言生成编排脚本 → 沙箱执行 → 仅回汇总"带来"几十个 agent 并行而主上下文不涨"。定位：开源影响力/作品集（用户既定，V1 已确认）。

- 决策者：个人开发者自己（免费工具，安装即决策）。来源：分发方式

## 5. 现有替代方案与切换动力

- 当前替代方案：
  1. **OpenCode 官方内置子代理**（@general、Explore Subagent，支持并行多工作单元）。来源：OpenCode 官方文档与社区文章。[行为]
  2. **ensemble 插件**（自动拆 1～4 个文件级子任务并行）。来源：2026-07 社区文章。[行为]
  3. 分批手动跑、多开会话。来源：推断 [直觉]
- 用户满意度/采用情况：未验证（零反馈，不知道用户用不用内置子代理、是否知道 ensemble）
- 切换成本：低（npm 装/卸，无数据迁移、无采购流程）——利好采纳，也利好流失
- 竞品对比：本插件差异化 = 确定性 JS 编排（可重放）、几十级 fan-out（vs ensemble 上限 4）、嵌套 workflow、TUI 进度树、逐 agent token 计量。已实现且有测试。[行为]
- **Why Now（Switch Trigger）**：未发现。无证据表明用户此刻正被推动换方案。OpenCode 用户"刚开始用 AI 编排"本身是潜在触发面，但无实证。[直觉]
- 凭什么换：编排复杂度和规模超出内置子代理能力时的落差。档位：[直觉]

## 12. 最大风险

1. **平台内置化（有实证，最高）**：官方已有子代理并行基础，从"会不会做"变成"什么时候收编编排层"。窗口期内差异化必须立住
2. **零反馈盲飞（持续）**：V1 报告指出的反馈真空未变，7 天行动未执行
3. **生态天花板**：OpenCode 用户基数本身有限 [确定：市场结构]
4. **下载量平台期**：1953 vs 上期 1929（+1.2%），自然流量见顶信号——无内容营销投入下不再增长 [行为]
5. 三线作战 vs <10h/周（V1 已指出，未变）

## 13. Kill Criteria

已出现的证伪信号：无（素材中无负面反馈，但也无正面反馈——零反馈本身是中性偏负信号）。

围绕关键假设设未来阈值：

1. 反馈漏斗装好后 30 天仍零用户反馈 → 用户是路过型，影响力路线不成立，降级为个人工具
2. OpenCode 官方 release notes 出现内置编排原语 → 插件存在感归零，重新评估（迁移内核或归档）
3. ensemble 或官方方案覆盖"确定性编排 + 嵌套 + 计量"任两项 → 差异化窗口关闭
4. 月下载连续 3 个月 <1500 → 生态天花板证实，停止投入新功能

（以上为决策阈值，非已发生问题。）

## 16. 下一步（7 天内）

续行 V1 计划（未执行），按新情报微调优先级：

1. **装反馈漏斗（1h）**：README 加"你用它做什么？开 issue 告诉我们" + issue 模板（使用场景/遇到的问题/为什么不用内置子代理）——最后一问同时验证 H1 和竞品认知

3. **写对比型案例文（3h）**：选题 2（对标 ensemble 上限 4 worker），带真实数字，发 X + 中文社区——对比文比功能文传播率高，且天然回答"凭什么换"
