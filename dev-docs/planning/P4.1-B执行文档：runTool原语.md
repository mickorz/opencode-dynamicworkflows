## 二、锁定契约

1. **签名**：`runTool(scriptPath, { args?, timeoutMs?, parseJson?, onFailure? })`，
   返回 `{ ok, exitCode, stdout, stderr, durationMs, parsed? }`
2. **失败语义**：缺省 `onFailure: "throw"`——非零退出码/超时/启动失败/maxBuffer 超限抛
   `TOOL_FAILED`（消息含 exitCode 与 stderr 摘要）；显式 `"return"` 返回对象。
   依据：node-contract 的 resolve 即 success 语义，返回失败对象不触发组合控制流
3. **Journal**：消耗 `scope.callSeq`（与 agent/checkpoint 同构，key 用 `scopedKey`）；
   每次执行经 `onAgentExecution` 追加 executions（成功也记，因 runTool 不写 entry 本体）；
   **不写 hash/result** → resume 永远 miss → 重跑；下游 agent 若 prompt 嵌入输出，
   变化经既有 prompt-hash 机制失效（专项测试锁定）
4. **计数与判定**：`toolCount` 独立计数、不计 agentCount（无 maxAgents 配额占用）；
   有效性判定 `agentCount === 0 && toolCount === 0` 才拒绝（纯 runTool Workflow 合法）
5. **边界**（五项，违反即 `SCRIPT_VALIDATION_ERROR` 或执行失败）：
   路径仅限项目目录内（realpathSync.native 归一后判定，含 symlink 逃逸拦截）；
   扩展名白名单 `.py/.js/.sh`（`.sh` 在 Windows 直接 execFile，启动失败即失败，不假定可用）；
   `args` 仅字符串数组（execFile 参数式，无 shell 注入面）；`timeoutMs` 缺省 30s；
   stdout/stderr 合计上限 1MB（maxBuffer，超限即失败）
6. **日志**：每次执行 `shared.log` 一行（路径/结果/耗时）——第一版 TUI 展示走日志区 +
   journal executions（Node Inspector 可查）；专项节点渲染（脚本路径/退出码/耗时的树节点）
   为后续增强，不阻断 B 验收

## 三、测试清单（tests/runtool.test.ts）

| 用例 | 断言 |
|------|------|
| 成功返回结构 | ok/exitCode/stdout/durationMs 齐全 |
| 缺省失败抛 TOOL_FAILED | recoverable、消息含 exitCode |
| fallback 换候选 | 第一候选 runTool 失败 → 第二候选执行 |
| sequence 停止 | runTool 失败后后续节点不执行 |
| onFailure return | 返回 {ok:false} 不抛错 |
| parseJson | stdout JSON → parsed；非法 JSON 不崩 |
| 纯 runTool 合法 | agentCount 0 + toolCount 1 通过 |
| 纯计算仍拒 | 无 agent 无 runTool 抛 SCRIPT_VALIDATION_ERROR |
| 边界 | 项目外/不存在/非白名单/symlink 逃逸/超时 |
| journal executions | 成功失败都追加且无 hash（resume 必 miss） |
| resume 下游失效 | runTool 输出变化 → 下游 agent prompt 变 → 重跑（fake runner 验证） |
