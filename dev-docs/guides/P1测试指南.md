## 测试二：journal / resume（两步）

**第一步：首跑建立 journal**

```
读取 scripts/resume-test.js 的内容，用 workflow 工具原样执行
```

完成后**记下输出头部的 runId**（形如 `run-xxxxx`），并确认 3 个 agent 全部"成功"。

**第二步：改脚本 + resumeFromRunId 续跑**

对 Main Agent 说（把 `<runId>` 换成第一步记下的值）：

```
用 workflow 工具执行下面的脚本（与上一次相比，B 的 prompt 已改），
并传 resumeFromRunId="<runId>"：

export const meta = { name: 'resume_demo', description: 'P1 journal/resume 演示：3 个 agent 顺序调用' }

phase('Explain')
const a = await agent('用一句话解释什么是 SHA256 哈希', { label: 'A-哈希' })
const b = await agent('用一句话解释什么是最长公共子序列', { label: 'B-前缀' })
const c = await agent('用一句话解释什么是缓存回放', { label: 'C-回放' })
return { a, b, c }
```

**通过标准**：
- 输出头部出现 **`1 个缓存回放`**
- agent 摘要里 **A-哈希 是 [缓存]**，B-前缀 与 C-回放 是 [成功]（改了 B 后，B 及其后的 C 都重跑——最长未变前缀语义）
- 结果 JSON 中 `a` 与首跑一致，`b` 变成了新问题的答案
- （可选）中断验证：重跑 acceptance-10docs 中途 Esc，输出会提示"已完成的 agent 已记入 journal，续跑请传 resumeFromRunId=..."；按提示续跑，已完成的分析回放不烧 token


通过标准：正常完成；日志区出现 `tier "nonexistent-tier" 未配置，回退会话默认模型...`（且只出现一次）。

**真实分层路由（可选，验证省钱开关）**：

1. 在 `examples/sample-project/.opencode-workflows/` 下新建 `model-tiers.json`（目录不存在则创建）：

```json
{
  "tiers": {
    "small": "<网关里便宜的模型，格式 provider/modelId>",
    "big": "<网关里强的模型，格式 provider/modelId>"
  }
}
```

2. 执行脚本：

```
export const meta = { name: 'tier_routing', description: 'tier 分层路由验证' }
const cheap = await agent('你是什么模型？一句话', { tier: 'small', label: '小模型' })
const strong = await agent('你是什么模型？一句话', { tier: 'big', label: '大模型' })
return { cheap, strong }
```

通过标准：两个 agent 的自述模型不同；输出正常。

## 测试四：质量 DSL（judgePanel / verify / checkpoint）

```
读取 scripts/quality-dsl-test.js 的内容，用 workflow 工具原样执行
```

**通过标准**：
- 执行到 checkpoint 时**弹出权限确认对话框**（允许 / 拒绝）——这是 P1-4 的 ToolContext.ask 通道，属首次真机验证点
- 选"允许"：结果 `adopted: true`；选"拒绝"：`adopted: false`，脚本继续返回
- 结果 JSON：`best.attempt` 是两候选之一，`best.score` 在 0-1 间；`verdict.real` 为布尔
- agent 摘要出现 `judge 1.1 / judge 1.2 / verify 1 ...` 等标签

**观察点（不确定项）**：若 checkpoint 没弹框而是直接通过了（拿 default），说明 ToolContext.ask 在无 UI 通道时静默放行或抛错被吃——记录实际行为发我。

## 测试五：worktree 隔离

```
读取 scripts/worktree-test.js 的内容，用 workflow 工具原样执行
```

**通过标准**：
- agent 报告的分支名形如 `wf/run-xxx-N-隔离写手`（worktree 分支）
- agent 报告的 git status 显示 `demo-note.txt` 新文件（在 worktree 里创建成功）
- 运行结束后：sample-project 主目录**没有** demo-note.txt；`git worktree list` 无残留；`git branch --list "wf/*"` 为空（自动拆除）

**失败排查**：
- 若日志出现"worktree 隔离不可用，降级共享目录" → git 执行环境问题，看括号里的原因
- 若 agent 报告的分支是 main（没进 worktree）→ directory query 路由未被服务端接受，这是已知真机验证点（需求文档 10.2.1），把现象发我
