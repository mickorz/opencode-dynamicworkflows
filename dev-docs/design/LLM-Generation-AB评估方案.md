# LLM Workflow Generation A/B 评估方案（P1-5）

> 目的：验证 Composite API（sequence/fallback/race）相比旧 API 是否真正提升 Main Agent 生成 workflow 的正确率与效率。
> 这是 P2 是否继续扩展 DSL 的唯一判据（计划原文：如果 Composite API 没有明显提升，不要继续扩 DSL）。
> 状态：方案与 prompt 集就绪，**实机执行待办**（需真实 LLM 会话，每条 prompt 两轮生成 + 一轮执行验证）

## 实验设计

```text
同一批 workflow 需求 prompt（20 条）
        ├── A 组：旧 API skill（agent/parallel/pipeline/workflow/retry/checkpoint）
        └── B 组：Composite API skill（上述 + sequence/fallback/race）
                ↓
        每条生成后立即实机执行一次
                ↓
        记录 8 项指标 → 汇总对比
```

- 生成模型固定同一版本、同 temperature（建议主会话默认配置不动）
- A/B 两组使用不同 skill 版本：B 组 skill 更新完成（P1-6）后截快照；A 组用 git 历史里的旧版 skill
- 每条 prompt 独立新会话生成（避免上下文污染）
- 执行验证在 examples/sample-project 内用 fake 语义的轻量脚本（agent prompt 均为固定文本回复类，控制成本）

## 指标（8 项）

| 指标 | 采集方式 |
|------|----------|
| 首次运行成功率 | 生成的脚本第一次 workflow 工具执行即成功（返回 result）的比例 |
| 语法错误率 | meta 信封/确定性 blocklist/参数校验类失败占比 |
| 控制流错误率 | 逻辑错误（顺序错、该 fallback 用了 if、race 语义写反等）占比 |
| 平均脚本长度 | 字符数（去除空白） |
| 修复轮数 | 从首次失败到成功需几轮「贴报错→改脚本」 |
| 输入 token | 会话消耗（OpenCode TUI 里 /usage 或会话统计） |
| 输出 token | 同上 |
| 人工可读性 | 1-5 分主观评分（结构意图是否一眼可读） |

## Prompt 集（20 条，五类各四条）

### 类别 1：简单串行（预期两组都不该用 sequence——考察 B 组是否会过度使用）

1. 分析一份需求文档，输出三个问题清单，再逐条给出解决建议
2. 先读取目录结构，再总结项目架构，最后写一段 README 简介
3. 依次翻译一段文案为英文、日文、回译中文，比较语义漂移
4. 先分析代码风格，再生成编码规范文档，最后自查一遍

### 类别 2：串行 + parallel

5. 分析需求后，前端、后端、测试三路并行实现，最后汇总
6. 先做技术调研，然后两个候选方案并行深入评估，最后对比择优
7. 解析一个 JSON 配置，三个字段校验并行，全部通过后汇总报告
8. 先生成摘要，再并行翻译为英/日/韩三语，最后检查术语一致性

### 类别 3：失败 fallback

9. 快速模型先生成方案，质量检查不通过则换强模型重做，再不行用规则兜底
10. 首选 CDN 源拉取数据，失败换镜像源，最后走本地缓存
11. 自动化测试失败后先尝试自动修复再测，仍失败转人工记录
12. 结构化抽取失败时降级为自由文本抽取，两者都失败标记待人工

### 类别 4：nested workflow（子流程编排）

13. 主流程编排「调研→设计→实现」三段子流程，设计段内部还有两路并行
14. 先跑一次通用分析子流程，按结果决定走「深挖」或「横向扩展」子流程
15. 三个独立子流程串成流水线，每段消费上一段的返回值
16. 父流程做质量闸门，不过关则调「返工」子流程，返工两次仍不过则终止

### 类别 5：复杂组合（race/嵌套组合/混合）

17. 三个模型并行抢答，任一成功即用其结果，其余取消，最后校验
18. 分析→（并行：方案A生成 / 方案B生成）→ 评审择优，失败链：评审失败→重新生成→再评审
19. 数据清洗主链五步串行，其中第三步失败自动换备用清洗器，链尾做 race 双模型校验
20. 先并行三路信息收集（每路内部两步串行），汇合后 fallback 式决策树三选一，最后 checkpoint 人工确认

## 判定标准（建议）

- B 组「首次运行成功率」提升 ≥ 10 个百分点 且「控制流错误率」下降 ≥ 1/3 → Composite 有效，P2 继续
- B 组在类别 1 出现明显 sequence 滥用（>50% 用了）→ skill 边界规则需强化后重测
- 其余情况 → 维持现状，冻结 DSL 扩展
